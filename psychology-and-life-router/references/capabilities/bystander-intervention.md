# 旁观者干预（求助与被求助）

## R — 原文 (Reading)

> 当有不止一个人能够在紧急事件中帮忙的时候，人们经常会假设其他人愿意或应该帮忙——于是他们自己就会退缩或不介入。……如果你发现自己处于需要帮忙的情境，应当尽可能让旁观者把责任集中到自己身上。你应当直接对某人指出，“你！我需要你的帮助”。
>
> — 格里格 / 津巴多，《心理学与生活（第19版）》，第16章 社会心理学 > 攻击、利他行为和亲社会行为

---

## I — 方法论骨架 (Interpretation)

"没人帮忙"最省力的解释是"人冷漠"，而它几乎总是错的。达利与拉塔内把"出手"拆成一条判断链，每一环都可能断，而且每一环都由情境变量而非人格决定：

**环节 1 注意到。** 忙到赶时间的人根本看不见。神学院学生实验中，迟到组只有 10% 提供帮助，按时组 45%，早到组 63%——而他们要讲的题目恰好就是"善良的撒马利亚人"，主题相关性完全没能抵消时间压力。

**环节 2 评价为紧急。** 帮助他人的行为取决于**花时间**对情境做出准确的评价。在模糊情境下，人会去看别人怎么做，而别人的不作为又被读成"这不是紧急情况"的证据（多元无知）——于是没人动这件事本身，会让所有人更确定不用动。

**环节 3 感到责任。** 责任分散：在场的人越多，落到每个人头上的主观责任越接近 1/N，而 1/N 低于"采取行动"的个人阈值。

**环节 4 决定怎么帮。** 知道该做什么，且有能力做到。

两个角色的解法不同。**作为求助者**（最可执行的一条）：不要对人群喊，要**点名到人并给出具体任务**。实验里只被问"你有时间吗"的旁观者袖手旁观；被问"你能照看一下我的手提箱吗"的人几乎都介入了，有些人甚至追到岸边抓住小偷。一个小小的请求建立起一种与他人之间的特殊联系，把扩散的责任重新个体化。

**作为旁观者**：反向动作是先对自己说"既然没人动，那就归我了"，把责任重新收拢到一个人头上；同时主动完成"评价为紧急"这一步——不要等别人先定义这是不是紧急。

推论到日常协作：群聊与群体邮件是责任分散的温床。在 200 人的群里发"谁熟悉这块？在线等"，几乎必然无人响应；点名到人 + 给具体任务 + 贴出现象与已排查步骤（降低对方的评价成本）几乎总能解决。群里的沉默通常是责任扩散，不是冷漠。

## A1 — 书中的应用 (Past Application)

### 案例 1: 达利与拉塔内的癫痫发作实验
- **问题**: 1964 年纽约吉诺维斯案——据报道 38 位公民在半个多小时里观看一名妇女被刺，无人在行凶过程中报警。这能不能用"冷漠和铁石心肠"解释？
- **方法论的使用**: 把惨剧拆成可在实验室操纵的单一变量——参与者认为在场旁观者的数量。男大学生单独在有对讲机的屋子里，讨论中听到其中一人癫痫发作求救；因变量是他向实验者报告的速度。
- **结论**: 干预概率对"想到的在场人数"高度敏感，与人格无关。作者的反问是"给这些旁观者贴上冷漠和铁石心肠的标签公平吗？"
- **结果**: 两人情境下的每一个人都会在 160 秒内干预；而当参与者认为自己是更大群体的一员时，有 40% 的人**从未**通知实验者说有一个同学病得很厉害。惨剧不需要坏人，只需要人多。

### 案例 2: 善良的撒马利亚人 — 赶时间的人看不见求助者
- **问题**: 价值观与主题启动能不能抵消情境压力？
- **方法论的使用**: 普林斯顿神学院学生要去一栋不熟悉的楼里布道，布道内容正是"善良的撒马利亚人"。随机分为迟到组、按时组、早到组；途中必经的走廊里有一个不停咳嗽和呻吟的萎靡男子。
- **结论**: 时间压力是最强的情境变量之一，它直接掐断判断链的第 1 环（注意到），进而也掐断第 2 环（没时间评价严重性）。
- **结果**: 迟到组只有 10% 提供帮助，按时组 45%，早到组 63%。机制作者未定论——或许被所关心的东西吸引而没注意到，或许注意到了但太匆忙没有足够时间关注情境的严重性。制度推论：如果你希望成员有助人行为（导师制、代码评审、跨部门支援），就不要把他们的日程排满，留白是亲社会行为的制度前提。

### 案例 3: 手提箱与收音机实验 — 一个请求就能逆转
- **问题**: 怎样才能让旁观者从"站在边上看"变成"介入"？
- **方法论的使用**: 实验者同谋在离开前对旁观者说两种话之一——"你有时间吗？"，或者"你能在我离开的时候照看一下我的手提箱/收音机吗？"随后另一名同谋当着他们的面把东西拿走。
- **结论**: 行为本身建立起一种与他人之间的特殊联系，把扩散的责任重新个体化；这是反驳"把人们没能制止小偷仅仅归因于冷漠"的又一例证。
- **结果**: 前一种情况没有引发参与者的责任感，小偷拿走东西时那些人只站在边上看着；而答应替别人照看东西的人几乎都介入了，有些人甚至追到岸边抓住小偷。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 你在一个群、邮件组或公开频道发了求助，长时间无人响应。
2. 你需要向不特定多数人求助（公开场合、线上社区、跨部门群、事故现场）。
3. 你在现场看到有人可能需要帮助，而周围的人都站着不动。
4. 你在设计一个响应机制：值班表、工单分派、事故指挥、举报通道、"大家都有责任"的公共地带。
5. 复盘一次"明明有人看见了却没人管"的事件——线上事故、公共区域异常、跨部门扯皮的灰色地带。

### 语言信号（用户的话里出现这些就应激活）
- "群里发了没人回" / "有没有人懂这个？在线等" / "谁有空看下？"
- "当时周围那么多人，没一个上去帮忙的" / "现在的人太冷漠了"
- "这个事不是我一个人能定的" / "大家都有责任" / "我以为有人在处理"
- 英文: "someone should do something" / "is anyone here familiar with...?" / "I assumed someone else was handling it" / "nobody helped"

### 与相邻 skill 的区分
- 与 `situational-force-audit` 的区别: 那个处理**持续存在的群体结构与规范**（角色、从众、服从、群体决策），产出是要拧的旋钮；本 skill 处理**此刻有一个具体的人正在等待帮助**，产出是把责任钉到某个人身上的一句话。判据：有没有一个此刻正在受害/等待帮助的具体对象？有 → 本 skill；只是问"这个组织为什么长期这样 / 规范怎么改" → `situational-force-audit`。
- 与 `attribution-audit` 的区别: 那个处理"已发生的行为，原因该归给谁"，是在做**归因**；本 skill 处理"接下来谁动手"，是在做**行动指派**。事后复盘"为什么当时没人管"时，解释部分归 `attribution-audit`（责任分散是情境，不是人品），但产出部分必须是本 skill 的点名到人——只解释不动手，等于什么都没做。
- 与 `stress-appraisal-coping` 的区别: 那个的对象是你自己承受的压力与应对；本 skill 的对象是"别人需要帮助"或"你需要别人帮忙"。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **判定是否存在"此刻正在等待帮助的具体对象"**
   - 确认有一个具体的、正在等待帮助的人或事，且理论上能帮忙的人不止一个。
   - 完成标准: 能说出"谁需要什么"以及"理论上能帮忙的人有几个"，且后者 ≥ 2。
   - 判停条件: 若没有具体的求助对象，只是在讨论一个长期的组织性问题（风气、规范、制度），转 `situational-force-audit`。

2. **确定你的角色：求助者 / 旁观者 / 机制设计者**
   - 完成标准: 明确标注为三者之一（可以同时是求助者与机制设计者）。
   - 判停条件: 若你是旁观者且现场存在即时人身危险，先执行现实中的应急动作（确保自身安全、拨打当地急救电话并明确指定现场某人去打），再回到本流程做复盘与机制设计。

3. **求助者侧：拆掉三个断点（点名 → 具体任务 → 降低评价成本）**
   - 完成标准: 改写后的求助消息同时满足三条：① 指名道姓（"@张三"或"那位穿红衣服的先生"）；② 给出**一个具体动作**而非开放式请求（"帮我确认这条 NetworkPolicy 是否阻断了 DNS"，而不是"能帮忙看看吗"）；③ 已贴出现象、已排查的步骤和你判断为紧急的理由，让对方不必再花时间评价。
   - 判停条件: 若你确实不知道该找谁，退一步先指名一个**角色/岗位**并说明选择理由，然后要求对方转派给具体的人并回你一个名字——绝不停在"谁有空看下"。

4. **旁观者侧：先完成"评价为紧急"，再把责任收拢**
   - 完成标准: 能说出一句"我判断这是紧急情况，因为 ___"，以及"既然没人动，归我了"或"我已把它交给 ___（具体人名）并确认对方接了"。
   - 判停条件: 若判断后确认不是紧急事件，明确结束本流程，不做无谓干预；若确认紧急但自己无力处理，转为求助者角色，执行步骤 3（点名到人）。

5. **机制设计者侧：消灭"集体负责"的表述**
   - 完成标准: 把每一个"大家都有责任"的地带改写成一个具名 owner + 一个后备 owner + 一条触发条件；值班表与轮值安排上每个时段有唯一责任人。
   - 判停条件: 若某个地带确实无法指定 owner，明确标注为"已知的责任扩散风险点"，并配一条兜底规则（如超时自动升级、无响应则默认由 A 接手）。

6. **组织侧前提检查与验收**
   - 先检查：被要求"主动助人"的人（导师制、代码评审、跨部门支援、值班响应）日程是否被排满——时间压力会直接掐断判断链的第 1 环。
   - 完成标准: 给出一条留白措施（减少并行任务、安排缓冲、把助人时间计入工时与考核），并确定一个可客观读取的验收指标：求助侧在 X 分钟内收到至少一个具名响应者的明确答复（"我来"或"转给某某"）；机制侧则记录下一次同类事件的响应时间，与上一次可比。
   - 判停条件: 若无法调整日程，明确告知用户"助人文化"类的倡导不会有实际效果（神学院学生实验里，刚要讲慈善的人因为赶时间就没有行慈善）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 你在分析一个长期存在的组织结构问题（为什么这个部门长期默许某种做法、举报通道为什么没人敢用、团队风气怎么改）→ `situational-force-audit`。本 skill 处理"此刻有一个具体的人需要帮助"。
- 你在解释一个已发生行为的责任归属（事后追责、复盘归因）→ `attribution-audit`。本 skill 的产出是**接下来谁动手**，不是谁该背锅。
- **非紧急的日常协作场景不要滥用点名**：把每一次普通的信息咨询都升级成"紧急 + 点名到人 + 指定 owner"，会消耗掉这个信号的效力，也会对被调用的人制造不必要的压力。点名用于"真的需要有人现在动手"的时刻；普通咨询可以点名，但不要加紧急话术。
- **不能用"责任分散"为见死不救开脱**：本 skill 解释机制，不提供豁免。作者本人的落点是动作——因为机制是情境的，所以它可以被设计掉；知道机制而不动手，解释不成立。

### 作者在书中警告的失败模式
- **failure_mode（CE48 责任扩散）**: 起点是基蒂·吉诺维斯案——据报道 38 位公民在半个多小时里观看一名妇女被刺，无人在行凶过程中报警。达利与拉塔内的实验量化了这个效应：两人情境下每个人会在 160 秒内干预；而当参与者认为自己是更大群体的一员时，有 40% 的人**从未**通知实验者。
- **mechanism**: 责任扩散的机制是责任的**主观分担**——当有多人在场，介入的主观责任被均摊到每个人头上，于是每个人都只承担 1/N，而 1/N 低于"采取行动"的个人阈值。同时存在**评价顾忌**：在不明确是否真为紧急事件的场合，人害怕误判造成的社会尴尬，而他人的不作为被当作"这不是紧急情况"的证据（多元无知）。第二个变量是**时间压力**（善良的撒马利亚人实验）：赶时间的人看不见求助者。
- 作者的提醒是别急着贴道德标签：**"给这些旁观者贴上冷漠和铁石心肠的标签公平吗？"**——把情境产物读成人格属性，这本身就是基本归因错误（CE47）。

### 旁观者效应不等于"人都是冷漠的"（必须写明的边界）
书中明确给出的是**多重原因**，不是单一的人性论断：
- **责任扩散**（在场人数越多，每人分到的主观责任越薄）；
- **情境模糊性**（需要花时间评价这到底是不是紧急事件）；
- **评价顾忌**（怕误判丢脸，于是看别人怎么做）；
- **时间压力**（赶时间的人根本看不见求助者）。
四个原因**全部是情境变量，全部可以被设计掉**——这正是作者给两个动作的根据：求助时指定具体的人，自己作为旁观者时先完成"评价为紧急"。书中数据也支持这个方向：答应替人照看东西的人几乎都介入了，有些人甚至追到岸边抓住小偷——人是愿意帮忙的，卡在机制上。反面提醒同样重要：不要因为少数无人施救的案例就假定"群体必然冷漠"，也不要用这条给自己的不作为找解释。

### 作者的盲点 / 时代局限
- 本书英文版成书于 2014 年，早于 2015 年可重复性危机的大规模重复验证。旁观者效应的核心实验（达利与拉塔内 1968、达利与巴特森 1973）年代久远，样本为美国男大学生与神学院学生，属 WEIRD 样本。近年对旁观者效应的重复与元分析总体支持"在场人数抑制干预"这一方向，但**效应量比教科书呈现的小**，且真实紧急情境下的干预率明显高于实验室估计——部分研究显示在可识别的紧急事件中，旁观者介入是常态而非例外。
- **吉诺维斯案本身的新闻叙事在后续调查中被修正**（并非 38 人全程冷眼旁观，也并非完全无人求助），本书沿用了 1964 年的原始报道版本。使用本 skill 时不要引用"38 人"作为精确事实，改用"这一案触发了旁观者干预的系统研究"这一表述。
- 书中"多元无知"的解释成立，但对线上场景（群聊、工单、邮件组）的外推是本书没有覆盖的：线上"看到但未回复"还会叠加通知疲劳与可见性不对称（你不知道别人看没看到），机制不完全等同，效果需要实测而不是照搬。
- 作者把这些研究放在"亲社会行为"章节，语气偏乐观（"一个小小的请求……几乎使得每一个旁观者都能够耐心地提供帮助"）。需注意请求本身的社交成本：在等级距离大或关系疏离的语境中，点名到人可能引发抵触，效果会打折——此时应同时给对方一个低成本的退出选项（"如果不行你帮我指个方向就行"）。

### 容易混淆的邻近方法论
- 与"号召大家多关心 / 呼吁责任感": 作者的解药方向相反——不是呼吁，而是**把责任个体化**。群体层面的呼吁不改变 1/N 的分母，只是让每个人更确定"已经有人在呼吁了"。
- 与"集体负责制": 集体负责正是责任扩散的制度形式。凡是没有落到具体人名的责任，按已知风险点处理，并配兜底规则。
- 与 `situational-force-audit`: 见 A2 区分。两者都谈"情境"，但那个谈的是长期结构，这个谈的是当下的一次干预。
- 与 `attribution-audit`: 见 A2 区分。复盘"为什么没人管"时先归因（那个），再指派（这个），顺序不能颠倒，也不能只做前者。
